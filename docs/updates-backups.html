Looking after it

Updates and backups

A PitchTribe screen can run for months untouched. Two things look after it: keeping a backup of your content, so a failed memory card is a ten-minute fix, and updating the software now and then.

Updating PitchTribe

Check which version you have in the dashboard under Settings → About, and what’s new on the releases page. To update, connect to the Pi and run the installer again:

curl -sSL https://pitchtribe.media/install.sh | sudo bash

Your content, playlists, screens and password are all kept. The screen goes blank for a moment while PitchTribe restarts.

Using guest Wi-Fi or several screens?

Repeat the options you installed with, or they’ll be left out. For example, on a Pi with guest Wi-Fi: curl -sSL https://pitchtribe.media/install.sh | sudo PITCHTRIBE_PORTAL=1 bash. On an extra screen: … | sudo PITCHTRIBE_SERVER=http://clubhouse.local bash.

Updating Raspberry Pi OS

This one looks after itself. PitchTribe installs the operating system's security fixes when you first install it, and then every night at about three o'clock, just before the backup — so the Pi is patched and the night's backup is taken from an up-to-date card.

Two things it deliberately leaves alone, because nobody is in the building at three in the morning:

  • It never removes software, so the screen can't lose Chromium overnight. The handful of updates that need something uninstalled wait for you.
  • It never restarts the Pi. A new kernel takes effect the next time the Pi reboots — no rush; the fix is installed either way.

So once or twice a year, when it suits the club, connect to the Pi and finish the job by hand:

sudo apt update && sudo apt full-upgrade -y && sudo reboot

The Pi restarts and the screen comes back by itself after a minute or two.

Checking what the nightly update did

The dashboard shows it, under Settings → About: when the Pi last checked, how many updates went on, and — the one to watch for — “a restart is waiting” when something needs the Pi restarted. It also says so plainly if the Pi has stopped being able to fetch updates, or if the nightly run hasn't happened for days, because both of those are silent otherwise.

Over SSH, sudo journalctl -u pitchtribe-os-update shows the last few nights, and /var/lib/pitchtribe/os-update-status.json holds the latest result. A Pi that's offline simply skips the night and catches up on the next one.

Backing up to a USB stick

Everything that makes your PitchTribe yours — content, photos and videos, playlists, screens, settings, guest Wi-Fi sign-ups and the password — can be copied to a USB stick plugged into the Pi, automatically, every night. If the memory card ever fails, you flash a new one, plug the stick in, and tap Restore. What goes on the stick is encrypted, so a stick that walks off doesn’t take the club’s guest list with it — which means there is one code to print and keep safe.

  1. Plug a USB stick into the Pi

    Any stick works as it comes (FAT32 or exFAT; ext4 too). 32 GB is plenty for most clubs; go bigger if you upload a lot of video. A small “flush” stick that barely sticks out, like a SanDisk Ultra Fit, is hard to knock out by accident. PitchTribe keeps its backups in a folder of their own, PitchTribe-backups, and leaves anything else on the stick alone.

  2. Choose it in the dashboard

    Open Settings → Backups. The stick appears within a few seconds. Tap Use this stick for backups — the first backup starts straight away, and it is encrypted.

  3. Print the recovery code

    The dashboard shows you a code of 24 letters and numbers, in groups of four, like ABCD-EFGH-JKMN-PQRS-TVWX-Y123. Tap Print, or write it down, and keep it somewhere other than with the stick — the club office folder, not the drawer the stick lives in. It is the one thing that gets your backups back if the Pi’s memory card fails. You can see it again any time from Settings → Backups → Show recovery code.

  4. Leave it there

    From now on PitchTribe backs up every night at about half past three, and keeps the last 30 nights. Photos and videos are copied once, not every night, so the stick fills up slowly. The Backups card shows when the last backup ran, how much space is left, and warns you if the stick has been taken out or is full. Back up now makes an extra one any time — handy before a big change.

Don’t see Backups in Settings?

USB backups arrived in PitchTribe 0.2. Check your version under Settings → About, and update if it’s older.

Why the backups are encrypted

A backup stick holds the whole club: every guest Wi-Fi email address, every photo and video, and the dashboard password’s hash. A stick is small, it lives in a cupboard in a building lots of people walk through, and it is easy to pocket. So PitchTribe encrypts what it writes. A stick that goes missing gives away nothing but the club’s name and the dates the backups were taken.

Two things can unlock it, and you need only one of them:

  • The Pi itself. A key kept on the memory card, readable only by the system, never included in any backup. This is what lets the Pi back up at half past three in the morning with nobody there, and it is why restoring onto the same Pi never asks you for anything.
  • The printed recovery code. For the day the memory card is the thing that died. A new card knows nothing, so the code is what proves you are the club.

Encryption arrived in PitchTribe 0.4.3. A stick set up from that version onwards is encrypted from its first backup. If the club was already backing up before then, nothing changes until you ask it to: open Settings → Backups and tap Encrypt these backups, which generates the code and shows it to you straight away. Switching it on doesn’t change the old backups — they stay as they are, readable. The next night’s backup, and every one after it, is encrypted. You can turn it off again from Settings → Backups → Stop encrypting; backups already written stay encrypted, and PitchTribe can still read either kind.

Lose both and the backups are gone

This is the one new way encryption can bite, and it is worth being plain about. If the memory card fails and nobody can find the recovery code, the backups on the stick cannot be opened — not by the club, not by a computer shop, not by us. There is no master key and no way to ask for one. That is what makes the stick safe to leave in a cupboard, and it is exactly why the code is printable: put it in the folder the club keeps its other paperwork in, the same day you set the stick up. A downloaded backup file kept on the club laptop is a good second string.

Restoring after a memory card fails

  1. Write a new memory card

    Follow the beginner’s guide steps 1–5 with a new card. Use the same hostname as before (or leave it blank if you did last time), so the dashboard keeps its address and the screen keeps its name.

  2. Plug in the backup stick and open the dashboard

    Open the dashboard on your phone as usual. Instead of setting it up, look under Restoring after a new memory card?: the backups on the stick are listed, newest first.

  3. Type the recovery code

    Because the card the backups were written from is gone, the screen asks for the printed code — the one from setting the stick up. Type it in; dashes, spaces and lower case are all fine, and there is no O, I, L or U in a code, so nothing can be mistaken for a 0 or a 1. A backup made before the club switched encryption on doesn’t ask for anything.

  4. Tap Restore from USB stick

    Everything comes back as it was at that backup — content, screens, settings and the old password — and the Pi carries on backing up to the same stick, encrypted, with the same recovery code as before. The screen goes blank for a moment; with a lot of video, allow a few minutes. Then sign in with the club’s usual password.

You can also restore an older backup while signed in, from Settings → Backups → Restore from the USB stick — useful to undo a big mistake. Changes made since that backup are lost.

A backup file, for safe keeping

A USB stick in the same Pi won’t help if the Pi itself is lost, stolen or fried by a power surge. Every so often, keep a copy somewhere else too:

  • Settings → Backups → Download backup saves everything as one .tar.gz file. Keep it on the club laptop or shared drive. With a lot of video it can be large.
  • To put it back — on a new card, or a replacement Pi — use Restore from a backup file… on the dashboard’s first-run screen, or Restore from file… in Settings.
Doing it from a terminal instead

Everything lives in one folder on the Pi, /var/lib/pitchtribe. To copy it by hand, connect with SSH and run:

sudo tar czf ~/pitchtribe-backup.tar.gz -C /var/lib/pitchtribe db.json media

That file can be restored from the dashboard like any downloaded backup, and it is not encrypted — you made it, so look after it accordingly.

The USB stick keeps its ordinary folder layout whether or not it is encrypted — PitchTribe-backups/<hostname>/snapshots/ for each night’s settings, media/ for the photos and videos — so any computer can see the stick and copy it. The contents of those files are encrypted (AES-256-GCM, a key per file), so copying the stick is useful as a second copy, but you can’t read it without going through PitchTribe. Each snapshot’s manifest.json stays readable on purpose: it is what lets the set-up screen list the backups before anyone has signed in or typed a code. Alongside it, keys.json holds the stick’s key wrapped twice over — once to this Pi, once to the recovery code — and never in the clear. Delete it and every snapshot on that stick becomes unreadable, so leave it alone.

Checking a download is genuine

You don’t have to do any of this — but if you want to be sure the card image you downloaded is the one we built, here is how.

Every release carries the image, a .sha256 checksum, and a build attestation. The checksum proves the file arrived intact; the attestation proves we built it, because it is signed by the build itself and cannot be replaced by whoever replaces the file. With the GitHub CLI installed:

gh attestation verify pitchtribe-rpi-arm64.img.xz --repo pitchtribe/pitchtribe-display

It prints the commit the image was built from. To check the checksum alone, on macOS or Linux:

shasum -a 256 -c pitchtribe-rpi-arm64.img.xz.sha256

The one-line installer installs the latest release, not the newest code, and stops rather than guessing if it cannot work out which release that is. To install a particular version, or the development branch:

curl -sSL https://pitchtribe.media/install.sh | sudo PITCHTRIBE_REF=v0.4.2 bash

What is in a backup

A backup contains the whole club: notices, photos and videos, screens, the dashboard password (hashed, not readable), your saved API keys, and every email address collected by the guest Wi-Fi sign-in. Those emails are personal data, which is why the USB stick is encrypted — but a downloaded backup file is not, so treat that one like the club’s membership list. A backup never contains the key that signs dashboard logins, so an old backup cannot be used to get back into a dashboard; nor does it ever contain the Pi’s own backup key or the recovery code, so a stolen stick can’t be unlocked with anything written on it.

Memory cards wear out

A good-quality A2 card in a Pi that runs all day usually lasts years, but cheap cards can fail sooner. With a USB backup, a spare card with the PitchTribe image already on it, kept in the club office, gets you back up in ten minutes.
